# 钩织图解语法规范 v0.1

这份文档定义本项目内部的**唯一真源（IR）**、文字图解的输出语法、符号约定，
以及"能不能钩得出来"的校验规则。任何生成器、渲染器、校验器都以此为准。

---

## 一、针法语义（一切推导的起点）

只支持短针体系，覆盖 amigurumi 绝大多数场景：

| 针法 | 符号 | 消耗上一圈针目 | 产生新针目 |
|---|---|---|---|
| 短针 single crochet | `X` | 1 | 1 |
| 加针 increase | `V` | 1 | 2 |
| 减针 decrease | `A` | 2 | 1 |

由此得到**两条守恒式**（校验器的核心判据）：

```
消耗的基针 bases = sc + inc + 2·dec   必须 == 上一圈针数 cₙ₋₁
产生的针目 tops  = sc + 2·inc + dec   必须 == 本圈针数 cₙ
两式相减即：        cₙ − cₙ₋₁ = inc − dec
```

第 1 圈没有"上一圈"，其针数由起始方式决定。

## 二、数据模型（IR）

```js
Pattern = {
  version: 1,
  name: string,
  gauge: { w: number, h: number },   // mm/针、mm/圈
  parts: Part[],
}

Part = {
  id: string,                        // 'head' | 'body' | 'arm-L' ...
  startType: 'magic-ring' | 'chain-ring',
  note: string,
  rounds: Round[],                   // rounds[i].n === i+1，必须连续
}

Round = {
  n: number,
  ops: [{ op: 'sc' | 'inc' | 'dec', count: number }],   // 有序、压缩后的 run 列表
}
```

**为什么 ops 必须有序**：顺序决定加减针在圈内的分布位置，
而分布位置决定形状是正圆还是偏心。只存总数是不够的。

## 三、文字图解语法

### 3.1 生成规则

一圈的 ops 先摊平成单针序列，再找**最小周期**压缩：

| 单针序列 | 输出 |
|---|---|
| `V V V V V V` | `6V` |
| `X V X V X V X V X V X V` | `(X,V)×6` |
| `X X V X X V …`（周期 3） | `(2X,V)×6` |
| `X X X V …`（周期 4） | `(3X,V)×6` |
| 无周期（素数长度） | `2X,V,3X,V` |

规则：
1. 若最小周期长度 = 1 → 写成 `N<符号>`，如 `6V`、`12X`
2. 若最小周期长度 > 1 → 写成 `(<周期> )×N`，周期内相邻同类压缩，如 `(2X,V)×6`
3. 无重复 → 直接罗列，逗号分隔
4. **行末括号里的数字 = 本圈总针数**，与 ops 推导出的 tops 必须一致

### 3.2 必须显式声明的三条约定

歧义的根源在约定不统一，所以输出里必须写死：

1. **起立针 / 引拔针不计入针数**
2. **玩偶按螺旋圈钩（不引拔）**——因此"第 N 圈从哪一针开始"是隐式的
3. **第 1 圈针数 = 起针后的实钩针数**（魔术环起 6 个短针即 c₁ = 6）

> 第 2 条尤其重要：螺旋钩没有引拔点，图解的行首是**隐式**的。
> 若某个生成器按"每圈引拔闭合"输出，行首会显式，两者不可混用。

### 3.3 语法（便于解析）

```
pattern   := header part+
header    := "# " name NEWLINE "线材密度……" NEWLINE 约定行
part      := "【" id "】" NEWLINE 起始行 NEWLINE round+
round     := "第 N 圈：" expr "(" total " 针)" NEWLINE (说明行)?
expr      := unit | unit "," expr | "(" unit ")×" reps | count symbol
unit      := symbol | count symbol
count     := [0-9]+
symbol    := "X" | "V" | "A"
```

## 四、符号对照（符号图 / SVG 用）

CYC（Craft Yarn Council）标准符号，与中文圈习惯并列：

| CYC 名称 | 中文 | 我们的符号 |
|---|---|---|
| chain (ch) | 锁针 | `○` |
| slip stitch (sl st) | 引拔针 | `·` |
| single crochet (sc) | 短针 | `X` |
| half double crochet (hdc) | 中长针 | `T` |
| double crochet (dc) | 长针 | `F` |
| sc2tog | 两针并一针（短针减针） | `A` |
| 3-dc cluster | 三长针枣形 | — |
| worked in back/front loop only | 后半针 / 前半针 | 画在针的**基部** |

两个易错点（CYC 原文特别标注）：
- `sc` 有**两个**通用符号，画哪个都合法；
- 后/前半针的符号画在**针的基部**，不是针顶。

## 五、校验规则

| 编号 | 级别 | 规则 |
|---|---|---|
| V000 | error | 图解没有任何部件 |
| V001 | error | 某部件没有任何圈 |
| V002 | error | 某圈产生 0 针 |
| **V003** | **error** | **本圈消耗的基针数 ≠ 上一圈针数**（核心：不可钩） |
| V004 | error | 单圈针数 > 上一圈的 2 倍（一个基针最多被穿 2 次） |
| V005 | error | 单圈针数 < ceil(上一圈 / 2)（减针不许跳针） |
| V006 | warn | 减针占该圈基针 > 50%，收口过陡 |
| V007 | warn | 圈号不连续 |
| V008 | warn | 单圈操作数 > 200，工作量大 |
| V009 | warn | 所有特殊针连在一起，会明显偏心 |
| V010 | error | gauge 非正数 |
| V011 | warn | 第 1 圈 < 3 针，起针过少 |
| V012 | warn | 最后一圈仍有峰值一半以上针数，未收口 |

**V003 是唯一的硬闸门**：它成立则"相邻两圈耦合"成立，图解必然可钩；
它不成立就是错图解，无论看起来多合理。

## 六、剖面 → 针数序列

```
r(y) = 剖面线性插值得到的目标半径（mm）
cₙ   = round( 2π · r(yₙ) / w )        yₙ = (n − 0.5)·h
```

随后做**耦合夹紧**（把违反 V004/V005 的圈拉回合法区间），
并用"均匀散布"算法把 inc/dec 铺到圈内（最小化偏心）。

### 必须暴露偏差

整数化和夹紧**一定**会修改序列，所以成品必然偏离目标轮廓。
`build.js` 的 `deviation()` 量化每圈偏差，界面必须显示：

- 最大相对偏差（%）
- 被夹紧的圈及原因

**不显示偏差就等于假装公式是精确的**，这是本项目的红线之一。

## 七、同源要求

```
IR ─┬─→ 文字图解（pattern.js）
    ├─→ 符号图 SVG（chart.js，待实现）
    └─→ 3D 回转体（web/app.js）
```

三条渲染路径**必须**只读 IR，不得各自维护一份针数。
若 3D 显示的形状与文字图解不一致，那是代码 bug，不是参数差异。
